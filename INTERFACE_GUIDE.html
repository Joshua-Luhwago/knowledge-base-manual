This guide follows the reference interface manual, with additional completed workflows, recorded browser demonstrations, API coverage and reproducible inputs. On-screen labels remain Chinese so that English readers can find the controls.

Evidence scope: The refreshed screenshots and interface tour were captured from this repository at http://127.0.0.1:5176, with Flask on 5004 and an isolated Neo4j database on Bolt port 7688. The import and library recordings use the same repository with Flask on 5002. The monitoring capture uses an isolated InfluxDB instance on 8087. 1. Quick start and workflow map

Use an existing project environment (venv/ or .venv/). Never install project dependencies in conda base. In separate terminals:

source venv/bin/activate
python app.py

cd frontend
npm run dev

Default development frontend: http://127.0.0.1:5173. Backend port comes from .env; the supplied example uses 5001. Vite proxies /api and /pdfs to that backend. The refreshed tour used isolated capture ports 5176/5004. A built frontend/dist can also be served by Flask.

Main workflow: import one file → extraction/cleaning → compare source and Markdown → edit if needed → 保存并入库 → find the document in 数据集管理 → use retrieval/graph/Q&A → enter an anomaly in 诊断报告 → open its saved report.

2. Home, navigation and appearance

Open 首页. The page presents the knowledge workflow, asset composition, processing-state counts, category distribution, condition-monitoring area and suggested/recent questions. Scroll down for module cards; 进入系统 and module links lead into workspaces. Summary, quality and distribution are supplied by distinct APIs, so their counts can differ.

Use the top navigation to change work areas. The theme switch toggles light/dark appearance and stores the choice in browser local storage. 设置 → 用户管理 opens /manage; 退出 currently returns to the home page.

3. Import and upload history

Open 知识导入. 开始导入 opens the upload workspace. The history table shows file name/type, destination category, upload time, state and available location actions. Use its search field, type filter (PDF/image/Excel/audio/video) and state filter (completed/processing/failed) to narrow the list. 查看定位 opens the corresponding dataset file when one has been committed.

In /parse/create, click or drag a single supported file into the upload zone. Fill 文档名称, select 保存栏目, or select + 新增栏目 and enter a name. Remove an incorrectly queued file before submitting. PDF inputs additionally expose 解析策略. Start processing using the upload action, then follow the timeline and log entries.

The file picker accepts PDF, Excel (xlsx/xls/xlsm), common images, audio and video extensions. Each displayed upload is one file. Internal queue code does not imply a multi-file batch picker.

5. Completed spreadsheet import and editing

Reproduce with manual-demo.xlsx. The sheet 主变压器时序 contains two synthetic readings for MANUAL-DEMO-001: 72/76°C and 42/46 MW, at 08:00/09:00 on 1 November 2026 (+08:00).

  1. Upload the workbook and name it Manual demo — synthetic transformer readings.
  2. Wait for 表格解析 and 文本清洗 to complete. The observed engine was openpyxl+pandas.
  3. Review the source table beside the Markdown table. Processing may open an enlarged preview automatically; use 关闭 to return to the workspace.
  4. Click 编辑, amend the Markdown, then 保存. The demonstrated edit explicitly labels the readings synthetic.
  5. Click 保存并入库. Find the saved workbook in the dataset, reopen it, and verify 抽取结果 contains the edited draft.

Observed result: the source workbook remained readable and the edited Markdown was retained after commit. For local indexing of new documents, set EMBEDDING_DOCUMENT_MODEL=voyageai/voyage-4-nano. A separate isolated append test added one document to a copy of the 5,719-vector Voyage 4 index, producing 5,720 vectors and ranking the new document first for its test query. The recorded workbook upload was not rerun for this indexing check. Knowledge-library import is separate from 状态监测 import into InfluxDB.

6. Dataset management, previews and recovery

Open 数据集管理. Filter using 资料分类 → 设备对象 → 业务场景, with 使用场景 as an additional facet. Search by document name/device type. Switch between 文档 and 图片, collapse the sidebar, use 上一页/下一页, or select rows with checkboxes. Selection alone does not expose a batch operation in this template.

Click a document name to open its preview. Use source preview, 抽取结果, 切分块, open-source-file, fullscreen and close controls. PDFs use an iframe; images show the original; workbooks show sheet tabs and cell tables. Some existing entries display 未知 because their title metadata is incomplete; use source/category context to identify them.

Open … → 编辑文档名称, change the title, then 保存; 取消 or Escape abandons the edit. The title-map change does not rename the underlying source file. … → 删除 soft-deletes the source and associated Markdown to the local trash and excludes it from visible results.

Demonstrated: the synthetic workbook was renamed Manual demo — verified rename, soft-deleted, restored using the actual backend recovery endpoint, and reopened. No pre-existing document was deleted. Recovery uses POST /api/pdfs/restore with {"file":"<relative source path>"}. A recovery drawer exists in the component, but the current template has no visible button opening it; use the API until that entry is wired. Trash records store a 30-day purge_after_ts; that field is not proof that a scheduled purge job runs.

7. Vector retrieval and index maintenance

There is no separate vector workbench in the active router. Inspect chunks in the dataset preview, or use the backend endpoints:

  • GET /api/vector/overview: index summary, distributions and sample chunks.
  • GET /api/vector/docs: document-level indexing information.
  • GET /api/vector/doc-chunks?doc_id=<id>&limit=200: ordered chunks and provenance.
  • POST /api/vector/search: query, optional top_k (1–100), category, doc_id. Returns scores, text and available source-page/clause/line metadata.

The search implementation reads a FAISS inner-product index, embeds the query, retrieves candidates, filters by document/category and excludes deleted documents. A dimension mismatch returns HTTP 409 and triggers a rebuild task. An absent index or unavailable embedding model must be resolved before successful semantic retrieval.

Index compatibility and result: The saved 1,024-dimensional Voyage 4 index accepts local voyageai/voyage-4-nano query embeddings with EMBEDDING_QUERY_MODEL=voyageai/voyage-4-nano; no index rebuild is needed. Set EMBEDDING_DOCUMENT_MODEL=voyageai/voyage-4-nano to encode newly added documents locally. Download Nano once with LOCAL_EMBEDDING_LOCAL_ONLY=0, then set 1 for offline use. Search returned HTTP 200 with three hits; an isolated append check grew a copy of the index from 5,719 to 5,720 vectors.

Maintenance endpoints are backend operations: POST /api/kb/build (combined), /api/vector/rebuild (vector only), /api/graph/rebuild (graph only). Poll GET /api/kb/build/<task_id> for stages, logs and result. A returned task ID means accepted, not completed. Existing indexes were not deliberately rebuilt for this manual.

8. Knowledge graph

Open 知识图谱. Enter equipment, a metric, a fault or standard in 统一检索, then click 搜索 or press Enter. The page requests a subgraph and evidence chains. Suggestions and topic chips focus matching entities. Select a node to inspect/focus it; drag/zoom the D3 network and use +, −, 适配. 刷新图谱 reloads; 图谱大屏展示/回到总览 reset filters.

The visible workspace includes node/edge counts, typed-node counts, current zoom, search results and evidence-chain summaries. Backend entity lookup supports name/type and query limits; chain lookup supports seed limit, chain limit and one/two hops. Typed extraction includes StandardClause, FaultMode, InspectionTask, MaintenanceAction, ThresholdRule, with relationships linking evidence, faults, inspections and actions.

Graph setup and result: Set NEO4J_URI, NEO4J_USER, and NEO4J_PASSWORD for a running Neo4j instance, then restart Flask. The graph demonstration uses an isolated database built from the saved vector chunks with KG_EXTRACT_MODE=rule and POST /api/graph/rebuild. Back up an existing database before this clean rebuild; follow progress at GET /api/kb/build/<task_id>. In the captured run, /api/graph/overview returned HTTP 200, and graph search returned a populated network and evidence chains.

9. Evidence-based questions

Open 知识问答. Choose a suggested category/question or type a question. Enter sends; Ctrl+Enter inserts a line break. The send button is disabled during execution. 新建对话 starts a fresh conversation; selecting history reopens a saved answer. The history context menu supports deletion of a saved question.

Answers can include inline 【1】 citations, source-document links and a right-hand 引用文本块 panel with up to five evidence excerpts. 查看文档 opens the associated dataset source; 复制 copies the excerpt. Inspect page, clause, section and line metadata where present. These fields describe available source provenance, not a guarantee that each old record has a resolvable PDF.

Configuration and result: With EMBEDDING_QUERY_MODEL=voyageai/voyage-4-nano, the saved Voyage 4 index accepts a local 1,024-dimensional query vector. Configure a working answer model such as local Ollama qwen2.5:7b. The captured fresh DGA question returned HTTP 200, an answer with inline citations and eight evidence chunks. The other answer screenshots show saved history.

10. Diagnosis: three input modes

Open 诊断报告 (/diagnosis). The tabs select 结构化异常, 自然语言, or 混合输入. Natural language supplies a question; structured mode supplies equipment, symptoms/signals and measured values; hybrid combines both. Switching modes changes the form used for submission.

Structured fields include equipment ID/name/type, station, component, model and voltage; observed phenomena and one-item-per-line symptoms/signals; measurement ID/name/key, value, unit, timestamp and source. Add measurements with + 添加测量, or 移除 an extra row. Enter attention/warning/alarm thresholds and select 数值越高越危险 or 数值越低越危险. History accepts one timestamp,value pair per line. Advanced configuration exposes case ID, retrieval top_k and debug output.

Reproduce the completed demo: click 加载示例, inspect its two measurements, then 运行诊断. The built-in example uses hybrid input. It supplies top-oil temperature 95°C (thresholds 85/90/95) and load rate 87% (80/85/95). The actual output classified them as alarm and warning, respectively, and overall risk as Critical. A persistent report was generated.

Read the result's anomaly summary, fault candidates, checks, maintenance actions, applicability, contradictions, missing evidence and rule hits. Upper/lower threshold direction changes the comparison; a missing threshold is not an automatic normal finding. Evidence-enriched thresholds and discrepancies are displayed when available.

Interpretation of this run: The synthetic example returned six vector evidence chunks (evidence_count=6) and 18 typed graph candidates. The saved report includes two input observations, 20 typed graph support items, six standard-clause items and one vector evidence item. The 85/90/95 thresholds were example inputs, not newly retrieved standard limits; the candidates are suggestions rather than confirmed diagnoses.

11. Saved reports and source evidence

Click 查看完整报告 after a successful run. The saved-report route requires a real report ID; this session generated rpt-1793689314-0fd6a86d. The report presents input facts and normalized measurements, thresholds/rules, candidates, inspections/actions, and supporting evidence/technical details. Expand 四、附加追踪与技术细节 to inspect pipeline and enrichment notes. Scroll through the full report; the screenshots show its beginning and lower sections.

Reports are persisted as local JSON under uploads/reports/. List them with GET /api/reports, load one with GET /api/reports/<report_id>, or rebuild a report from an available run using POST /api/reports/from-run/<run_id>. Run detail is held in process memory, while saved report files survive restart. Keep the report ID to reopen the document.

Evidence buttons open a resolved PDF reference or the dataset document when source metadata is available. /api/references/pdf/<token> requires a registered token. This report lists two input observations (SCADA/EMS) and 21 typed graph support items.

The application has no dedicated report PDF-export button in this view. The Chinese/English PDFs accompanying this manual are generated documentation. Use browser printing separately if a diagnosis report must be printed.

12. Condition monitoring

Open 状态监测. Its separate file picker imports equipment series directly into InfluxDB. Choose an Excel workbook and click 上传并导入时序数据. Recognized sheet-name markers are 主变压器时序, GIS时序, 断路器时序, 主变压器运行日志. Each usable sheet needs timestamp or log_date, plus device_id. The monitoring-demo.xlsx workbook contains 24 synthetic readings for two devices, including top_oil_temp_c and load_mw.

For 单台设备多指标, select data type and device, toggle metric chips and choose 归一化对比/原值对比. Normalization supports shape comparison; read the result table for original values/units. For 单指标多设备, choose a metric and toggle device chips. 刷新 reruns the current selection; the lower query table shows returned data.

Configuration and result: Start InfluxDB OSS v2 and set INFLUXDB_URL, INFLUXDB_ORG, INFLUXDB_BUCKET and INFLUXDB_TOKEN in .env, then restart Flask. The isolated demo uses port 8087; /api/timeseries/ping and /api/timeseries/overview returned HTTP 200. Uploading monitoring-demo.xlsx wrote 24 points for two devices to its demo bucket, and both chart modes displayed populated series. CSV files are supported when their filename contains a recognized measurement marker; .xls uses xlrd.

On repeat import, the importer replaces points only for each incoming measurement and device within its date interval. The isolated demo bucket is separate from any production time-series database.

13. Accounts and management

The top 登录 / 注册 button has no bound click handler in App.vue. 设置 → 用户管理 navigates to /manage. That page displays permissions, monitoring, configuration and audit cards; 进入管理台 has no bound action. 退出 returns home without calling the authentication logout endpoint. These visible controls are not a completed account-management workflow.

The backend does implement combined email-code registration/login: send code → verify code → store issued session tokens → refresh → logout. Its routes are /api/auth/send-code, /verify-code, /refresh, /logout. Verification creates the user when necessary. SMTP, authentication settings and the local SQLite store support this service. See auth_api_quickstart.md for request/response fields. No email was sent and no real account was created for this manual.

  -H 'Content-Type: application/json' \

The submitted hybrid request is retained as diagnosis-request.json; the actual output is diagnosis-run.json.

curl -X POST http://127.0.0.1:5002/api/diagnosis/run \
  -H 'Content-Type: application/json' \
  --data-binary @docs/manual/samples/diagnosis-request.json

16. Command-line tools and troubleshooting

Run from the repository root using the project interpreter. PYTHONPATH=. lets scripts import core reliably.

venv/bin/python main.py --input-root pdfs --output-root pdfs/markdown --clean
venv/bin/python main.py --clean-only
venv/bin/python main.py --full-page-ocr --overwrite --clean
PYTHONPATH=. venv/bin/python scripts/import_timeseries_excel.py /path/to/data.xlsx
venv/bin/python scripts/import_dga_excel.py /path/to/dga.xlsx --skip-ingest
PYTHONPATH=. venv/bin/python scripts/evaluate_retrieval_strategies.py --help
venv/bin/python scripts/eval_kg_extraction.py
Tool What it does / required input
main.py Bulk PDF conversion and optional cleaning; --clean-only cleans existing Markdown; --overwrite replaces prior output.
import_timeseries_excel.py Uses the same InfluxDB importer and replacement semantics as monitoring. Requires the recognized sheets and live InfluxDB.
import_dga_excel.py First-sheet headers must start H2, CH4, C2H6, C2H4, C2H2, 故障类型; generates a knowledge summary and can ingest it. --category, --basename, --skip-ingest control output.
evaluate_retrieval_strategies.py Compares full-document, sliding-window, paragraph and recursive splitting using embedding or TF-IDF retrieval; supports FAISS/NumPy search and configurable chunk size/overlap/top-k. Consult --help.
