1. 启动与工作流程

使用项目已有的 venv/ 或 .venv/ 环境，不得向 conda base 安装项目依赖。在两个终端分别运行：

source venv/bin/activate
python app.py

cd frontend
npm run dev

默认开发前端为 http://127.0.0.1:5173。后端端口读取 .env，示例配置为 5001。Vite 将 /api、/pdfs 转发至后端。更新后的界面全览使用隔离的 5176/5004 截图端口。构建后的 frontend/dist 也可由 Flask 提供页面服务。

主流程： 上传单份资料 → 抽取与清洗 → 对照源文件和 Markdown → 必要时编辑 → 保存并入库 → 在数据集管理定位 → 检索、图谱或问答 → 在诊断报告输入异常 → 打开持久化报告。

2. 首页、导航与主题

打开首页，查看知识建设流程、资产类型构成、处理状态统计、分类分布、状态监测区域及推荐或近期问题。向下滚动可见业务模块卡片，通过进入系统或模块链接打开工作区。总览、质量与分布来自不同接口，统计值可能不同。

顶部导航用于切换模块。主题开关在明暗模式间切换，选择保存在浏览器本地存储。设置 → 用户管理进入 /manage；当前退出操作返回首页。

3. 导入入口与上传历史

打开知识导入，点击开始导入进入上传工作区。历史表显示名称、类型、保存栏目、上传时间、状态及可用定位操作。可使用名称搜索、文件类型筛选（PDF、图片、Excel、音频、视频）及状态筛选（已完成、处理中、失败）。文件已保存入库时，查看定位打开相应数据集条目。

在 /parse/create 点击上传区域或拖入单份支持的文件，填写文档名称，选择保存栏目；选择**+ 新增栏目时填写栏目名。排队文件选错时先移除。PDF 还可选择解析策略**。提交后观察处理时间线与日志。

文件选择器接受 PDF、Excel（xlsx/xls/xlsm）、常见图片、音频与视频扩展名。界面每次上传一份资料；内部队列逻辑不代表已有多文件批量选择器。

6. 数据集管理、预览与恢复

打开数据集管理，按资料分类 → 设备对象 → 业务场景筛选，并可附加使用场景条件。搜索框用于文档名称或设备类型检索；可切换文档/图片、收起侧栏、使用上一页/下一页，或勾选行。当前模板中，勾选本身未提供批量处理操作。

点击文档名称打开预览，切换源文件、抽取结果和切分块，也可打开源文件、全屏及关闭。PDF 使用内嵌页面，图片显示原图，Excel 提供工作表标签和单元格表格。部分已有条目因标题元数据不完整而显示未知，需结合源文件和分类辨认。

点击**… → 编辑文档名称**，修改标题并保存；取消或 Escape 放弃修改。重命名更新标题映射，不改变底层文件名。… → 删除将源文件和相关 Markdown 移入本地回收区，并从可见结果排除。

已演示： 将合成工作簿改名为 Manual demo — verified rename，软删除，再调用实际后端恢复接口，最后重新打开。未删除任何原有文档。恢复接口为 POST /api/pdfs/restore，请求体 {"file":"<源文件相对路径>"}。组件包含恢复抽屉，但当前模板没有可见打开按钮，需通过接口恢复。回收记录写入 30 天后的 purge_after_ts，该字段本身不能证明已有定时清理任务执行。

7. 向量检索与索引维护

当前路由没有独立向量工作台。可在数据集预览中查看切分块，或使用后端接口：

  • GET /api/vector/overview：索引摘要、分布与示例文本块。
  • GET /api/vector/docs：按文档汇总索引信息。
  • GET /api/vector/doc-chunks?doc_id=<id>&limit=200：有序文本块与来源信息。
  • POST /api/vector/search：提供 query，可选 top_k（1–100）、category、doc_id；返回分数、文本及可用页码、条款和行号。

检索读取 FAISS 内积索引，对问题向量化，召回候选，再按文档、分类过滤并排除已删除资料。维度不匹配时返回 HTTP 409 并触发重建任务。索引缺失或嵌入模型不可用时，需先解决相应问题。

索引兼容性与结果： 已有 1,024 维 Voyage 4 索引可使用本地 voyageai/voyage-4-nano 查询向量：设置 EMBEDDING_QUERY_MODEL=voyageai/voyage-4-nano，无需重建索引。设置 EMBEDDING_DOCUMENT_MODEL=voyageai/voyage-4-nano 可在本地编码新增文档。首次下载设置 LOCAL_EMBEDDING_LOCAL_ONLY=0，离线使用时改为 1。实测检索返回 HTTP 200 和三条命中；隔离副本的增量验证将向量数从 5,719 增至 5,720。

维护接口包括 POST /api/kb/build（综合构建）、/api/vector/rebuild（仅向量）、/api/graph/rebuild（仅图谱）。使用 GET /api/kb/build/<task_id> 查询阶段、日志和结果。返回任务 ID 只表示已接受，不表示完成。本次未主动重建已有索引。

8. 知识图谱

打开知识图谱，在统一检索输入设备、指标、故障或标准，点击搜索或回车。页面请求局部图谱与证据链；建议项和主题标签用于定位实体。选中节点后可检查或聚焦，支持拖动、缩放及 +、−、适配。刷新图谱重新加载；图谱大屏展示/回到总览重置筛选。

工作区显示节点数、关系数、类型化节点数、缩放比例、搜索结果及证据链摘要。后端实体接口支持名称、类型和数量限制；证据链接口支持种子数量、链路数量以及一跳或两跳。类型化抽取包括 StandardClause、FaultMode、InspectionTask、MaintenanceAction、ThresholdRule，并建立证据、故障、检查与措施之间的关系。

图谱配置与结果： 为运行中的 Neo4j 设置 NEO4J_URI、NEO4J_USER、NEO4J_PASSWORD，然后重启 Flask。图谱演示使用独立数据库，通过 KG_EXTRACT_MODE=rule 和 POST /api/graph/rebuild 从已有向量文本块构建。清理重建前应先备份已有数据库，并通过 GET /api/kb/build/<task_id> 查看进度。本次录制中，/api/graph/overview 返回 HTTP 200，图谱搜索得到有节点和关系的网络及证据链。

9. 带证据的知识问答

打开知识问答，选择推荐类别、示例问题或自行输入。Enter发送，Ctrl+Enter换行，执行期间发送按钮禁用。新建对话开启新会话；点击历史条目重新打开已有回答，历史项上下文菜单支持删除记录。

回答可包含行内 【1】、来源文档链接，右侧引用文本块最多展示五条证据摘录。查看文档打开相关数据集资料，复制复制文本块。可查看已有的页码、条款、章节与行号；这些是可用来源信息，并不保证每条旧记录都有可解析的 PDF 链接。

配置与结果： 设置 EMBEDDING_QUERY_MODEL=voyageai/voyage-4-nano 后，本地 Nano 为已有 Voyage 4 索引生成兼容的 1,024 维查询向量。再配置可用的回答模型，如本地 Ollama qwen2.5:7b。录屏中的新油色谱问题返回 HTTP 200、带行内引用的回答和八条证据文本块；其他回答截图展示已有历史。

10. 三种输入模式的诊断

打开诊断报告（/diagnosis），在结构化异常、自然语言和混合输入间切换。自然语言模式提交问题；结构化模式提交设备、症状、异常信号及测量；混合模式同时提交两者。切换模式会改变提交表单。

结构化字段包括设备 ID、名称、类型、站点、部件、型号、电压等级，异常现象和每行一项的症状/信号，以及测点 ID、名称、指标键、数值、单位、时间和来源。通过**+ 添加测量增加条目，通过移除删除多余测量。可输入注意、预警、告警值，并选择数值越高越危险或数值越低越危险**。历史序列每行填写 timestamp,value。高级配置提供案例 ID、检索 top_k 和调试输出。

复现已完成演示： 点击加载示例，检查两项测量，然后运行诊断。内置示例使用混合输入：顶层油温 95°C（阈值 85/90/95），负载率 87%（阈值 80/85/95）。实际结果分别为 alarm、warning，综合风险为 Critical，并生成持久化报告。

结果包含异常摘要、故障候选、检查建议、处置措施、适用性、矛盾、缺失证据及规则命中。上限/下限方向决定比较方式；缺失阈值不等于正常。有证据补全阈值或阈值差异时会显示相应内容。

本次结果含义： 合成示例返回六条向量证据（evidence_count=6）和 18 个 typed 图谱候选。保存的报告包含两条输入观测、20 条 typed 图谱支持项、六条标准条款证据及一条向量证据。85/90/95 是示例输入，并非新检索得到的标准限值；候选建议不是已确认的诊断结论。

11. 持久化报告与来源证据

运行成功后点击查看完整报告。报告路由必须使用真实 ID；本次生成 rpt-1793689314-0fd6a86d。页面展示输入事实、归一化测量、阈值和规则、故障候选、检查与措施，以及支持证据和技术细节。展开四、附加追踪与技术细节可查看流水线和证据补全记录。需向下滚动阅读完整报告，截图展示开头及下方内容。

报告以 JSON 持久化在 uploads/reports/。使用 GET /api/reports 列表查询，GET /api/reports/<report_id> 读取，或在运行记录仍可用时使用 POST /api/reports/from-run/<run_id> 重建报告。运行记录保存在进程内存中，报告文件可跨重启保留；请保存报告 ID。

存在来源元数据时，证据按钮可打开已解析的 PDF 引用或数据集文档；/api/references/pdf/<token> 需要已注册 token。本次报告列出两条 SCADA/EMS 输入观测和 21 条 typed 图谱支持项。

当前报告页面没有专门的 PDF 导出按钮。本手册附带的中英文 PDF 是文档构建产物；需要打印诊断报告时可另用浏览器打印。

12. 设备状态监测

打开状态监测。这里的独立文件选择器将设备时序直接写入 InfluxDB。选择 Excel 工作簿并点击上传并导入时序数据。可识别的工作表名称标记为主变压器时序、GIS时序、断路器时序、主变压器运行日志。有效表需包含 timestamp 或 log_date，以及 device_id；monitoring-demo.xlsx 提供两台设备共 24 条合成记录，包含 top_oil_temp_c 和 load_mw。

在单台设备多指标模式中选择数据类型和设备，通过指标标签控制曲线，选择归一化对比/原值对比。归一化适合比较变化形态，原值和单位应结合结果表读取。单指标多设备模式选择指标并切换设备标签。刷新重新执行当前查询，下方表格显示返回数据。

配置与结果： 启动 InfluxDB OSS v2，在 .env 中配置 INFLUXDB_URL、INFLUXDB_ORG、INFLUXDB_BUCKET 和 INFLUXDB_TOKEN，再重启 Flask。独立演示实例使用 8087 端口；/api/timeseries/ping 与 /api/timeseries/overview 均返回 HTTP 200。上传 monitoring-demo.xlsx 向演示 bucket 写入两台设备共 24 个点，两种图表模式均显示曲线。CSV 文件名需含可识别的测量类型标记；.xls 使用 xlrd。

重复导入时，导入器只替换输入 measurement 和设备在对应日期区间内的数据。独立演示 bucket 与生产时序数据库分开。

13. 账号与平台管理

App.vue 顶部登录 / 注册按钮没有绑定点击处理。设置 → 用户管理跳转 /manage；该页显示权限角色、运行监控、系统配置及审计日志卡片，进入管理台也未绑定操作。退出只返回首页，不调用后端登出接口。这些可见控件不构成已完成的账号管理流程。

后端已实现邮箱验证码合并注册/登录：发送验证码 → 验证 → 保存会话令牌 → 刷新 → 登出，接口为 /api/auth/send-code、/verify-code、/refresh、/logout。首次验证可创建用户，服务依赖 SMTP、认证配置及本地 SQLite 存储。请求与返回字段见 auth_api_quickstart.md。本次未发送邮件，也未创建真实账号。

15. 接口示例与完整目录

直接请求接口时使用后端端口。JSON 接口返回成功或错误字段，需同时检查 HTTP 状态与 ok；上传使用 multipart 表单。将示例 ID 和路径替换为实际返回值。

curl http://127.0.0.1:5002/api/vector/overview
curl http://127.0.0.1:5002/api/reports
curl -X POST http://127.0.0.1:5002/api/vector/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"变压器油温过高","top_k":5}'

本次提交的混合输入保存在 diagnosis-request.json，实际返回保存在 diagnosis-run.json。

curl -X POST http://127.0.0.1:5002/api/diagnosis/run \
  -H 'Content-Type: application/json' \
  --data-binary @docs/manual/samples/diagnosis-request.json

该 POST 会生成新的本地报告。schema/example/validate 接口针对诊断 schema 契约；/api/diagnosis/run 使用运行时封装，含 input_type、question、structured_input、top_k、case_id、include_debug。需检查结构，不能将 schema 示例不经转换直接当作运行请求。

16. 命令行工具与故障处理

在仓库根目录使用项目解释器。PYTHONPATH=. 可确保脚本找到 core。

venv/bin/python main.py --input-root pdfs --output-root pdfs/markdown --clean
venv/bin/python main.py --clean-only
venv/bin/python main.py --full-page-ocr --overwrite --clean
PYTHONPATH=. venv/bin/python scripts/import_timeseries_excel.py /path/to/data.xlsx
venv/bin/python scripts/import_dga_excel.py /path/to/dga.xlsx --skip-ingest
PYTHONPATH=. venv/bin/python scripts/evaluate_retrieval_strategies.py --help
venv/bin/python scripts/eval_kg_extraction.py
工具 功能与必要输入
main.py 批量 PDF 转换与可选清洗；--clean-only 仅清洗已有 Markdown；--overwrite 覆盖已有结果。
import_timeseries_excel.py 使用与监测页相同的 InfluxDB 导入器及区间替换语义，需要有效工作表和运行中的 InfluxDB。
import_dga_excel.py 首表表头须以 H2, CH4, C2H6, C2H4, C2H2, 故障类型 开始，生成知识摘要并可入库；--category、--basename、--skip-ingest 控制输出。
evaluate_retrieval_strategies.py 比较全文、滑动窗口、段落与递归切分，支持 embedding/TF-IDF 检索、FAISS/NumPy 搜索及块大小、重叠、top-k 参数；详见 --help。
eval_kg_extraction.py 依赖 docs/kg_extraction_eval_gold.json 对类型化抽取评分；本快照缺少该金标文件，需先提供数据。
Worker 模块 core/doc/pipeline_worker.py、multimodal_worker.py 是上传服务调用的子进程入口，不是额外操作页面。

这些维护与评估命令依据源码说明，未为本手册重新运行并冒充新实验结果。名称含 2 后缀的文件是重复源码，不是额外注册的产品功能。

现象 检查与处理
前端可打开但接口失败 检查后端端口与 Vite 代理，区分本仓库和其他正在运行的副本。
5173 已占用 Vite 使用 strictPort；停止冲突服务或明确使用其他端口并匹配后端。
图谱搜索无结果 检查 Neo4j URI 和凭据；备份数据库后使用 /api/graph/rebuild 从已有文本块构建图谱内容。
监测连接失败 启动 InfluxDB OSS v2，在 .env 中设置 URL/org/bucket/token，重启 Flask、检查 /api/timeseries/ping 后导入规定格式的 Excel。
问答显示 Hugging Face/缓存错误 已有索引使用 Voyage 4；设置 EMBEDDING_QUERY_MODEL=voyageai/voyage-4-nano 并首次下载 Nano，同时配置可用的回答模型。
向量检索返回 HTTP 409 查询与索引维度不同，检查返回的重建任务并等待成功。
抽取完成但数据集中找不到 完成保存并入库，检查任务和 dataset_file；抽取成功不等于已提交。
已有条目标题为“未知” 查看原文与分类，通过重命名补充标题。
报告无法重新打开 使用持久化 report ID；run ID 不同，且进程内运行记录可能在重启后消失。
Markdown 无法播放视频 直接打开 MP4 链接，或使用 HTML 版；PDF 展示静态画面。
